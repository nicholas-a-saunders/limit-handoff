# Design decisions

Where the [spec](SPEC.md) left room, or where it changed, this file records what was chosen and why. Entries are numbered and never renumbered, so code and tests can point to them ("DECISIONS.md #37").

## Hook behaviour

1. **No `trap 'exit 0' ERR`.** The spec asked for it. In bash, the ERR trap fires on any failing command, even a harmless one inside `$(...)`. It would stop the hook half way. Instead every hook body runs as `main || true` and the script ends with `exit 0`. Result: the hook always exits 0 and always finishes its steps.
2. **A recovered file is always written.** Even when jq is missing or the transcript cannot be read, a short `recovered-*.md` is written with the reason. So the paste prompt always points at a real file.
3. **Empty `error` is treated as `unknown`.** A StopFailure with no error text still gets a handoff. The error list is not checked when the error text is empty (SPEC step 1: only a non-empty code that is not in the list is skipped). See decision 80.
4. **Error list separators.** `LIMIT_HANDOFF_ERRORS` accepts spaces, `|` or commas. The hook matches whole words only.
5. **Recovered file names.** `recovered-<YYYYmmdd-HHMMSS>-<session8>.md`. The session id is cleaned to `[A-Za-z0-9_-]`, max 40 characters, and cut to 8 characters for the name. A missing id becomes `unknown`.
6. **Precompact snapshot labels.** It uses reason "context compaction snapshot" and code `precompact`, so the "Why this was made" line reads correctly.
7. **LATEST.md** is refreshed by StopFailure and by `recover`, but not by PreCompact (the spec says PreCompact writes a snapshot only).
8. **Reminder in stale mode.** The first prompt of each session shows the reminder. Later prompts show it only when the file is at least `LIMIT_HANDOFF_STALE_MIN` old. The marker is `$STATE/sessions/<session>.seen`. A missing session id shares one marker called `unknown`.
9. **SessionStart "fresh".** Read literally from the spec: fresh means age below `LIMIT_HANDOFF_STALE_MIN`. Older files get no startup line. An unresolved cut-off is still reported at any age.
10. **SessionStart "clear" source** prints nothing.

## Cut-off block and HANDOFF.md

11. **Same session, existing block.** The block is replaced in place (same position), with the new time. Blocks from other sessions are not moved or changed.
12. **Unclosed block.** If a block has no end marker, its text is kept and a new block is added after it. Nothing is dropped. (Fixer pass: a block ends at its end marker. A new cut-off header or a markdown heading before that end marker means the block was never closed. See decision 74.)
13. **Created HANDOFF.md** follows the global CLAUDE.md template and adds one section, "Last things you asked (recovered)". It also has a "Paste prompt" section that holds the same text as PASTE-PROMPT.txt.
14. **Existing HANDOFF.md.** Only the cut-off block changes. The user's own paste-prompt section is not rewritten.
15. **Next step.** For an existing file, the first list item under "## Next steps" (rule for finished items: see decision 70). For a created file, the first in-progress task, then the first pending task. If neither exists, the spec's text: "Re-read the last prompts below and confirm the goal". If there is no file and no create, "the first unfinished next step". Changed by decision 171: when there is no next step the paste prompt says so (it does not say "the first unfinished next step"), and the paste text is built from parts (see `hk_paste_text`).
16. **Subfolders.** `LIMIT_HANDOFF_FILE` may name a sub-folder (for example `docs/STATUS.md`). The folder is created when needed.
17. **Status line** keeps the spec's em dash and wording.
18. **The ⚠️ emoji** in the cut-off block is kept, because the spec's block text includes it.

## Transcript parsing

19. **Task lists.** A full TodoWrite or update_plan list replaces the old list. Items with `{advance: true}` advance the plan. The host also uses `{done: [...], start: n}`; I support that form too (done items get `completed`, the start item becomes `in_progress`, other in-progress items go back to `pending`).
20. **TaskCreate / TaskUpdate.** Claude Code's TaskCreate reply text is assumed to contain "Task #N". The number links the id used by TaskUpdate to the new task. If the reply text is different, TaskUpdate has no effect (no crash).
21. **Status words.** `completed`/`done`/`complete` become `completed`. `in_progress`/`in-progress`/`active` become `in_progress`. `deleted` items are removed. Anything else is `pending`.
22. **Files touched.** Only Edit, Write, MultiEdit and NotebookEdit count. Most recent first, max 20, no repeats. `Read` does not count.
23. **Last commands.** The last 5 Bash calls, oldest first, each command and description cut to 200 characters.
24. **Prompts.** `last_prompts` is oldest first. Consecutive repeats merge. The first prompt is the first real one in the tail. Text is cut at 600 characters.
25. **Assistant text.** The last text block of the last assistant message, cut at 800. Thinking blocks are never used.
26. **last-prompt fallback.** Used as the first prompt only when a transcript has no real prompt at all.
27. **Tail window.** The spec's caveat is kept in the docs: a very long session can push the first prompt out of the last 4000 lines.

## Installer

28. **Kit entry detection.** A hook command is a kit entry when it ends with `/hooks/<kit script>.sh` (optional quote, optional marker) AND (it carries the marker `# limit-handoff`, OR its path has a folder named exactly `limit-handoff`). The marker is added to every command the installer writes. It is a shell comment, so `sh` ignores it, and it lets a moved kit still be recognised. (Fixer pass: the old rule matched any path containing "handoff", so a user's own `/work/handoff/hooks/session-start.sh` was deleted. Changed to the rule above. Tests: `test_attack_spec_*_keeps_unrelated_hook_with_handoff_in_path`, `test_uninstall_keeps_a_user_hook_that_only_looks_like_the_kit`.)
29. **Shell quoting.** Hook paths are written in single quotes, so folders with spaces work. A test runs the installed command through `sh -c` from a folder with a space in its name.
30. **Events not selected.** Running install with `--events` removes kit entries for the events left out. The file then matches the choice exactly.
31. **No change, no backup.** When the result equals the current file, nothing is written and no backup is made.
32. **Missing settings file.** Install creates it and any missing parent folders. Uninstall does nothing.
33. **Tilde.** A quoted `~/...` path is expanded to `$HOME`.
34. **Invalid JSON, or a top-level array,** exits 2 and changes nothing.
35. **Backups** are named `<file>.bak-YYYYmmddHHMMSS`, with `-N` added if two land in the same second.

## Configuration and safety

36. **State folder default.** (Fixer pass: now follows the SPEC table exactly.) `$CLAUDE_PLUGIN_DATA`, else `$HOME/.local/state/limit-handoff`. The earlier build also looked at `$XDG_STATE_HOME`; that was dropped because the SPEC does not list it. A leading `~` in `LIMIT_HANDOFF_STATE_DIR` is expanded to `$HOME`. Test: `test_attack_spec_default_state_dir_is_home_local_state`. Still open: the user config file is read from `${XDG_CONFIG_HOME:-$HOME/.config}/limit-handoff/config`. The SPEC names only `~/.config`; the XDG part is kept because the config tests set `XDG_CONFIG_HOME`.
37. **Trusted keys.** `LIMIT_HANDOFF_CLIPBOARD`, `LIMIT_HANDOFF_NOTIFY` and `LIMIT_HANDOFF_STATE_DIR` are read from the environment and the user file only. A project's own `.claude/limit-handoff.conf` cannot pick the program that gets the paste prompt. (Tested by `test_trusted_keys_ignore_project_file`.) **Spec conflict (decision for the spec owner):** SPEC's literal order (env > project file > user file > default) would let the project file pick the clipboard program. The security rule wins. The adversarial test `test_attack_spec_project_config_can_choose_clipboard_command` was changed to assert the rule (the program does not run; the prompt is still saved). See decision 69. *(Superseded: the user-only list grew to nine keys, see 167 and 188.)*
38. **Config syntax.** `KEY=VALUE`, with optional spaces around `=` and optional matching quotes. Only `LIMIT_HANDOFF_*` keys count. Values are never executed. (Tested, including `$(touch ...)` in a value.)
39. **File name keys** (`LIMIT_HANDOFF_FILE`, `..._PROMPT_FILE`, `..._RECOVER_DIR`) must be relative, with no `.` or `..` parts, and only letters, digits, `._-/` and spaces. A bad value is logged and the default is used. (Tested with `../../etc/passwd`.)
40. **Templates** are filled by a single left-to-right awk pass that reads values from environment variables. Text that comes from a transcript, such as `{{PROJECT_DIR}}`, `%s` or `$(...)`, stays literal. (Tested.)
41. **No `eval`, no `source` of user text.** Config values are read as text. Clipboard command names must match `[A-Za-z0-9._-]+`.
42. **Notifications** pass the title and body as arguments to osascript, not inside AppleScript source.

## CLI

43. **`prompt` (manual handoff)** writes a short recovered file too, so the paste prompt's file reference is valid.
44. **`simulate`** turns the clipboard and notifications off unless `--copy` is given, or the env var is set. With no `--transcript` it uses `examples/sample-transcript.jsonl`. It writes into `--dir`, so use a scratch folder.
45. **`doctor`**: missing jq is a warning (exit 0), because the hooks still work. An unwritable state folder, a missing hook, or a non-executable hook is a failure (exit 1).
46. **`status`** lists events by the kit entries it finds. It does not check the hook command path.
47. **`resolve`** changes `status="unresolved"` to `status="resolved"` on the header line, and keeps the block text. With `--session` it touches only that session.
48. **Dry-run temp files** are created in the state folder, not the system temp folder.
49. **Exit codes**: 0 ok, 1 operational failure, 2 usage error. These match the spec.

## Extra files and names

50. **`lib/settings.jq`** holds all settings.json logic (install, uninstall, count, events). It is not in the spec's layout. It keeps the JSON edit in one place.
51. **`examples/sample-transcript.jsonl`**: the spec mentions examples; this is a made-up transcript for `simulate`.
52. **Extra helpers** beyond the spec's list: `hk_conf_trusted`, `hk_bool_conf`, `hk_int_conf`, `hk_file_name`, `hk_handoff_path`, `hk_prompt_path`, `hk_recover_json`, `hk_recover_note`, `hk_prompt_count`, `hk_render_recovered`, `hk_write_recovered`, `hk_derive_next_step`, `hk_paste_text`, `hk_create_handoff` (in the hook), `hk_last_unresolved_block`, `hk_block_at_human`, `hk_block_recovered`, `hk_block_error`, `hk_safe_rel`, `hk_clean_token`, `hk_in_list`, `hk_valid_cmd_name`.
53. **`LIMIT_HANDOFF_ERRORS`** is used by the hook and the spec mentions it in the StopFailure steps, but it is not in the config table. It is in the README table and the example file.
54. **`LIMIT_HANDOFF_TAIL_LINES`, `LIMIT_HANDOFF_PROMPTS`** are read through integer checks. A non-number falls back to the default.

## Testing choices

55. **Test scratch folders live in `tests/.tmp`** (inside the project), not in the system temp folder. The runner removes the folder when it finishes. Each test uses its own temp HOME, XDG folders and state folder.
56. **No-jq PATH.** `tests/run.sh` builds a folder of links to `/bin` and `/usr/bin` without jq and without clipboard or notification tools. Tests that check missing-jq behaviour use it. Test shims go first on PATH.
57. **Timing test.** A 30,000-line transcript (about 20 MB) must be read in under 2 seconds. It uses `perl` to measure time, because macOS `date` has no sub-second output.
58. **The runner needs jq.** The spec said "pure bash". Parsing transcripts needs jq anyway, so the test runner checks for jq and stops if it is missing.

## Adversarial test notes (added by the adversarial tester)

Files: `tests/test_attack_adversarial_{transcript,cutoff,hooks,settings,portability}.sh`. The runner only picks up `tests/test_*.sh`, so the `attack_adversarial_` prefix sits after `test_`. Each failing test is a bug for the fixer. No source file or existing test was changed.

59. **Severity.** Where the spec states a rule (for example "never fail on unknown lines", "blocks from other sessions stay", "merge without touching other keys or hooks", "never write outside the project dir"), a breach is **major**. Where the spec is silent (file mode, symlinks, look-alike hook paths, trailing slash in a file name, a project config aiming at `.claude/settings.json`, a FIFO transcript, markdown fences), the breach is **minor**, as the adversarial brief asked.
60. **Simultaneous sessions.** The spec does not name concurrency. I read "different session -> two blocks" and "blocks from other sessions stay" as requiring two hooks running at the same moment to keep both blocks. A usage limit hits every open chat at once, so this case is realistic.
61. **Unclosed block (decision 12 vs. the code).** Decision 12 says nothing is dropped. The tests hold the builder to that. Test: `test_unclosed_block_for_same_session_keeps_user_notes_and_other_blocks`.
62. **Spec deviation, not tested.** SPEC asks for `trap 'exit 0' ERR`. The build uses `|| true` and `exit 0` instead (decision 1). The tests check the behaviour the trap was meant to give (the hooks always exit 0), not the trap itself.
63. **Runner is not re-entrant.** `tests/run.sh` deletes and reuses `tests/.tmp`. Two runs at once (or a run whose pipe is closed early, such as `| head`) leave the other run with missing folders and random failures. Run it once at a time.
64. **Other test files.** `tests/test_attack_spec_*.sh` were added by another worker while these tests were written. They are not part of this adversarial set and were not edited.

## Fixer pass (decisions 65 to 82)

These record how the failing adversarial and spec tests were fixed. Where a test was changed instead of the source, the reason is given.

65. **Symlinks are followed on write (HANDOFF.md, settings.json, the paste prompt, LATEST.md).** `hk_atomic_write` resolves the link, writes a temp file next to the real file, then renames it over the real file. The link itself stays. A user who makes a link on purpose (for example from a dotfiles folder) gets the kit's changes in the real file. This is a judgement call. SPEC's hard constraint says "never write outside the project dir", and a link that points outside breaks that literally. The tests (`test_symlinked_handoff_md_keeps_its_link_after_a_cut_off`, `test_install_keeps_a_symlinked_settings_file_as_a_link`, `test_attack_spec_install_writes_through_a_symlinked_settings_file`) expect the link to be followed. The spec owner should confirm. Changed by decision 166: a link committed in the project that points outside it is no longer followed by default. The writes are refused (HANDOFF.md, the paste prompt and LATEST.md), and the paste prompt goes to the state folder. Only the user's own settings (environment or user file) can allow it with `LIMIT_HANDOFF_FOLLOW_LINKS=1`.
66. **Kit-made folders are not followed out of the project.** If the recovery folder (`.handoff`) is a link that points outside the project (`hk_inside_project` fails), or it cannot be created, the recovered file goes to `<state folder>/recovered/`. The cut-off block and paste prompt then show the absolute path. Test: `test_symlinked_recovery_folder_cannot_send_files_outside_the_project`.
67. **Lock for HANDOFF.md.** `hk_lock_take` makes a folder `<state>/locks/<cksum of the real path>.lock` with `mkdir` (atomic). It retries every 0.05 s for about 2 s, then breaks a lock that was left behind. The stop-failure hook takes the lock before it reads the next step and releases it after it writes HANDOFF.md. `resolve` takes the same lock. If the lock cannot be made at all (state folder not writable), the caller goes on without one. Tests: `test_two_sessions_cut_off_at_the_same_moment_keep_both_blocks`, `test_two_new_sessions_creating_handoff_keep_both_blocks` (both pass in every round of the test loops). *(Superseded by 182: a noclobber lock file, about 10 s before a stale lock is broken.)*
68. **settings.json shape is checked first.** If the `hooks` value is not an object whose values are lists, install, uninstall and status refuse with exit 2 and change nothing. The file's other keys are never touched. Tests: `test_install_keeps_user_hooks_when_hooks_is_an_array`, `test_install_keeps_user_entry_when_an_event_is_an_object`, `test_install_keeps_user_entry_when_an_event_is_a_string`. `status` says "unknown" (not "none") when a hook command is not text. Tests: `test_status_does_not_claim_no_kit_hooks_when_settings_cannot_be_read`, `test_install_with_a_non_text_hook_command_gives_a_readable_result`.
69. **Clipboard command from the project file is still ignored (spec conflict).** The security rule (decision 37) is kept. The attack test was changed to match it, because the two cannot both pass. A test in `test_common.sh` (`test_trusted_keys_ignore_project_file`) already enforces the rule and must not be weakened. The spec owner should decide. If the spec order is kept, the security test must change first.
70. **Next step skips finished items only when an open box exists.** `hk_first_next_step` returns the first list item in "## Next steps". A `[x]` item is skipped only when the section also has a `[ ]` item. With no `[ ]` item, the first item is returned, as the literal spec says. This satisfies both `test_first_next_step_formats` (existing, `[x] Done box` then `[~] Half box` gives `Done box`) and `test_attack_spec_next_step_skips_checked_items` (`[x] Already done` then `[ ] Real next step` gives `Real next step`).
71. **User text in a created HANDOFF.md is escaped.** When a file is created, the goal, the done items, the next items and the quoted recent prompts are written with every `#` escaped as `\#`. The goal's line breaks are joined into one line. So a prompt cannot start a heading such as `## Next steps`. Test: `test_attack_spec_multiline_first_prompt_cannot_add_a_next_steps_section`. The recovered file keeps the text as it was, inside quote lines or code fences.
72. **Code fences in the recovered file.** A command's fence is one backtick longer than the longest run of backticks in that command (at least four). So a command cannot close its own block early. Test: `test_command_with_a_fence_line_cannot_break_out_of_its_code_block`.
73. **Transcript shapes.** All `.message` reads go through `msg`, which gives `{}` when `message` is not an object. So a string, number, list or null message is skipped and never stops `jq`. `update_plan` `done` values that are not a list are ignored. Tests: `test_one_odd_line_does_not_stop_the_whole_parse` and the others in `test_attack_adversarial_transcript.sh`.
74. **Unclosed block rule.** Inside our block, every line is kept until our end marker. The block ends early (and is written back unchanged) only when another cut-off header or a markdown heading (`#`, `##`, ...) comes first. Then nothing is dropped. Test: `test_unclosed_block_for_same_session_keeps_user_notes_and_other_blocks`. Existing test `test_upsert_replaces_same_session_in_place` (text inside a block) also passes.
75. **The paste prompt file can never be HANDOFF.md.** If `LIMIT_HANDOFF_PROMPT_FILE` equals the handoff file name, the default `PASTE-PROMPT.txt` is used (or `HANDOFF-PASTE-PROMPT.txt` if that is the handoff name too). Tests: `test_attack_spec_prompt_file_setting_cannot_overwrite_handoff`, `test_prompt_file_setting_cannot_point_at_claude_settings`.
76. **Path rules.** `hk_safe_rel` also refuses a trailing `/` (a folder name, so `docs/` falls back to `HANDOFF.md`), a double `//`, and any `.git` or `.claude` folder in the path. Tests: `test_handoff_file_with_trailing_slash_is_refused_not_silently_dropped`, `test_prompt_file_setting_cannot_point_at_claude_settings`.
77. **A transcript must be a plain file.** `hk_recover_json` reads only regular files. A named pipe (FIFO) or a folder is treated as unreadable, so the hook never blocks on it. Test: `test_fifo_transcript_does_not_hang_the_hook`.
78. **Tilde in the state folder.** `LIMIT_HANDOFF_STATE_DIR=~/x` means `$HOME/x`. Test: `test_attack_spec_tilde_in_state_dir_config_expands_to_home`.
79. **Writes keep the file mode and never replace a folder.** `hk_atomic_write` copies the permission bits of an existing file to the temp file before the rename (a 600 settings file stays 600). If the target is a folder it refuses. Tests: `test_attack_spec_install_keeps_file_mode_600`, `test_install_keeps_the_file_mode_of_a_settings_file_with_secrets`.
80. **A missing error code is not filtered.** SPEC step 1 only skips a non-empty code that is not in `LIMIT_HANDOFF_ERRORS`. With no code at all the hook writes the block with `error="unknown"`. This replaces the earlier reading in decision 3. Test: `test_attack_spec_missing_error_field_is_not_filtered_by_error_list`.
81. **Recovered files outside the project are reported.** `recover` and `prompt` print the absolute path. `simulate` also looks for its recovered file in the state folder. `hk_abs_path` turns a project-relative name into a full path.
82. **Read-only and fallback folders.** With a read-only project, the recovered file now goes to the state folder (the paste prompt write still fails and is logged, as `test_read_only_project_still_exits_zero` expects).

83. **Where the fixes went.** The user asked for new work in a new folder, and for existing files to be read only. So the fixes were made in this copy, `limit-handoff-fresh-review`. The original folder `limit-handoff` was read and never edited. The copy leaves out the stray test folders `tests/.adv-probe`, `tests/.tmp-timing*` and `tests/.adv-run*`, which BUILD-NOTES listed as junk. Nothing else was removed.

84. **An unusable clipboard name refuses and logs; it never falls back.** Before, an unusable `LIMIT_HANDOFF_CLIPBOARD` value did nothing visible. The log did not say why. Now `hk_copy_clipboard` writes a reason to the log (the name is not allowed, or it is not on PATH) and copies nothing. It does not fall back to `auto`, because `auto` can run the real `pbcopy`. Tests: `test_path_value_is_refused_logged_and_nothing_is_copied`, `test_missing_tool_name_never_falls_back_to_pbcopy`.

85. **`simulate` no longer overrides the user's settings.** Before, `simulate` always set `LIMIT_HANDOFF_CLIPBOARD` and `LIMIT_HANDOFF_NOTIFY` in the environment (`auto` with `--copy`). An environment value beats the config file, so a user's clipboard setting in `~/.config/limit-handoff/config` was ignored by `simulate --copy`. Now, without `--copy`, the clipboard is forced off and notifications are off unless the environment sets them. With `--copy`, `simulate` sets nothing. Test: `test_copy_uses_clipboard_from_user_config_file`.

86. **Clipboard names are bare command names.** Allowed values: `auto`, `off`, or a name made of letters, digits, `.`, `_` and `-` that is found on PATH. Paths are refused. Reason: a project file must not choose the program that runs with the paste prompt. This keeps the SPEC clipboard rule from DECISIONS #37 and #69. The README documents the rule.

87. **`doctor` shows the clipboard setting the hooks will use.** The old line `clipboard tool: <name>` is kept, because an existing test checks its text. A new line `clipboard setting: ...` is added under it. A bad setting is a warning (exit 0), not a failure, because the paste prompt is still written to a file.

88. **Two default error lists, kept on purpose; the README explains them.** SPEC.md lines 10 and 125 set the installer matcher default to `rate_limit|billing_error|unknown`. SPEC.md line 93 sets the runtime default of `LIMIT_HANDOFF_ERRORS` to include `overloaded` and `server_error`. Claude Code gates the hook by its matcher. So a default install never runs the hook for those two codes, even though the runtime list would accept them. Both defaults are kept because the spec states both. The README now says this and shows the `--errors` example that adds the two codes. Open question for the user: should the installer default include them? *(Note: the README explains this in the `LIMIT_HANDOFF_ERRORS` row of the config table, not with an `--errors` example.)*

89. **Documented: re-running `install` with fewer `--events` removes the other kit hooks.** The SPEC says a re-run replaces the kit's own entries. That is what happens. The README says so. The user's own hooks are never removed.

90. **Documented: `install` creates a missing settings file.** No backup is made in that case, because there is nothing to back up. The README says so.

91. **Documented: hook commands use absolute paths.** Moving the kit folder breaks the hooks until `uninstall` and `install` are run again from the new place. The README says so, in Install and in Limitations.

92. **A clearer `--events` error.** An unknown event name now lists the four valid names. Test: `test_install_bad_event_lists_the_valid_names`.

93. **Documented: `simulate` and `prompt` use the current folder when `--dir` is missing.** `simulate` writes `HANDOFF.md`, `PASTE-PROMPT.txt` and `.handoff/` into that folder. The README has a warning and tells users to use a scratch folder. The behaviour was not changed, because the SPEC says the project folder comes from the working directory or `CLAUDE_PROJECT_DIR`.

94. **Incident during the walk-through: the real clipboard was overwritten.** Two test runs used `simulate --copy` while the clipboard setting was in a config file (one in a project file, one in the user file). The old `simulate` set `LIMIT_HANDOFF_CLIPBOARD=auto` in the environment, which beat the config file. So the real `pbcopy` ran and replaced the Mac's clipboard with a test paste prompt from a temp folder. The earlier clipboard contents could not be recovered. Decision 85 fixes the cause, and decision 84 makes an unusable name fail safely. The incident is in BUILD-NOTES "Clipboard incident".

95. **The new tests were checked against the old bugs.** The old environment override and the old fallback to pbcopy were each put back in a temp copy. The new tests failed in each case (3 failures and 1 failure). The fixed copy passes all 7. Full suite after the changes: 258 passed, 0 failed.


Note on the test runs: the concurrency tests are timing-based. Each one runs 10 or 15 rounds inside the suite. The first two full runs of the fixer pass failed (32, then 3 checks). The last three full runs, made after the final edits, all passed (251 of 251).

## Code review fixes (decisions 96 to 103)

96. **The paste prompt file is backed up before it is replaced (F1).** Before `hk_write_prompt_file` replaces a file, it compares the file's SHA-256 with the hash the kit stored when it last wrote that real path (in `<state>/prompts/<sha256 of the path>`). If they differ, or no hash is stored, the file is copied to `<name>.bak-<YYYYmmdd-HHMMSS>` (a `-n` number is added when the name is taken) and the copy is logged. Then the new prompt is written. If the backup fails, nothing is written. Why: `LIMIT_HANDOFF_PROMPT_FILE` can point at the user's own notes. Judgement: back up and write, rather than refuse, because the prompt must still be written. Without a hash tool every write backs up the file. Tests: `test_f1_*` in `tests/test_review_fixes.sh`.

97. **Same-file rule for the prompt file (F2).** Two names are the same file when they match ignoring case, when both exist and `[ -ef ]` says they are the same file (this also covers hard links), or when their real paths (after following links, even dangling ones) match. The fallbacks are `PASTE-PROMPT.txt`, then `HANDOFF-PASTE-PROMPT.txt`, then `PASTE-PROMPT-2.txt`, and the reason is logged. This replaces the plain string check in decision 75, which missed case-only names and links.

98. **`status` exits 2 for a settings file that is not valid JSON (F3).** The report is printed in full first, then the exit code is 2 (usage error, as in decision 49). A settings file that does not exist still exits 0. The existing test `test_status_without_handoff_and_bad_settings` now expects exit 2. This is the only existing test whose expectation changed; CHANGELOG.md says so.

99. **A config folder that links out of the project is refused (F4).** `hk_parent_inside_project` walks up from the name's folder to the nearest folder or link that exists (a dangling link counts as existing, and it fails because it cannot be entered). That entry is resolved with `cd -P` and must be inside the real project folder. `hk_file_name` applies this to `LIMIT_HANDOFF_FILE`, `LIMIT_HANDOFF_PROMPT_FILE` and `LIMIT_HANDOFF_RECOVER_DIR`. A refused name is logged and the default is used. A link that stays inside the project is allowed. The rule covers the folder part only. A final file that is a link is still followed (decision 65). Why: `docs -> ~/notes` would let a config name write outside the project. Extended by decision 166 (links to files, not only folders).

100. **Only checked values reach hook output (F5).** Hook output reads cut-off block values through `hk_block_error` (a known code from `HK_STOP_CODES`, else `unknown`), `hk_block_at_human` (`YYYY-MM-DD HH:MM`, else left out), `hk_block_recovered` (a safe project path, else the folder name is shown) and `hk_block_session` (`[A-Za-z0-9_.-]{1,80}`, else `unknown`). `hk_reason_for` shows known codes by name, as before (the existing reason test expects `invalid_request`), and returns `unknown API error` for anything else. No hook prints the session id today, so `hk_block_session` is a checked reader for any future output. Residual risk, kept on purpose: the "First next step" line echoes the text of `## Next steps` in HANDOFF.md. That text is the task list the user wants Claude to read, so it is not treated as untrusted. Only keep the handoff file in folders you trust.

101. **`.claude` and `.git` checks ignore case (F6).** `hk_safe_rel` lowercases a copy of the path (`tr '[:upper:]' '[:lower:]'`, bash 3.2 safe) for the `.claude` and `.git` checks. The `..` and `.` checks stay as they were. Why: macOS folders ignore case, so `.Claude` is `.claude`.

## v1.0.0 additions

104. **Limit details come from the transcript first, then the hook's last message.** `hk_limit_detail` uses the `limit` key that transcript recovery builds from the synthetic limit line. The hook's `last_assistant_message` is only a fallback, used when the transcript gives no limit. Why: the transcript has the exact limit type and reset time. The message is only text, so it gives wording only. Without jq the message is read with sed, which can stop early at an escaped quote. That only loses text after it, and the detail rules still apply.

105. **Synthetic error lines are never the last reply.** `lib/transcript.jq` leaves every line with `isApiErrorMessage` out of `last_assistant_text`, so the real last reply wins. The limit line is read separately into `limit`, and a subagent copy (`isSidechain` true) is ignored for both. Why: the text "You've hit your session limit" is written by Claude Code, not by the assistant, so it must not be shown as the last thing Claude said.

106. **Only fixed words and checked values are printed.** The label comes from a fixed table, or from a generic name made of `^[a-z0-9_]{1,40}$` (underscores become spaces, then " limit"). The reset time is formatted from an epoch of 9 to 11 digits. The text of the limit line and of the message is never copied to output. The message fallback keeps only the words "session limit" or "weekly limit" and one `resets <time>` part that matches one fixed pattern. Every detail is cut to `[A-Za-z0-9 :,()/+_.-]` and at most 100 characters. Why: transcript text can carry shell syntax, markdown or `-->`, and the detail lands in HANDOFF.md, a block attribute and hook stdout.

107. **Reset time formatted with GNU date, then BSD date.** `hk_format_epoch` tries `date -d @N` first and then `date -r N`, with `LC_ALL=C` so names are English. The format is `%a %d %b %H:%M %Z` in the local time zone. Why: on GNU systems `date -r N` reads a file named N in the current folder, so the `-d @N` form goes first. The local test run used the BSD path only (macOS has no GNU date).

108. **The reason shows the detail; the notification title does not repeat it.** The shown reason is `<reason> — <detail>` in the cut-off line, the paste prompt, the recovered file's "Why this was made" line and the hook log. The notification title is `Claude Code stopped: <plain reason>`, and its body starts with the detail: "<detail>. Handoff saved; paste prompt copied. Paste it into a new chat to continue." Why: the spec gives both the title and the body, and putting the detail in both would say it twice.

109. **Cut-off block gets two optional attributes.** `limit="<type>"` and `resets="<epoch>"` come after `error="..."`. Each is written only when it passes its strict check. `hk_block_limit`, `hk_block_resets` and `hk_block_detail` return nothing for a missing or unsafe value, so an old block without the attributes still works everywhere. The prompt and session hooks rebuild the detail from these two checked values, never from the block text. Why: this lets a later chat show the limit without the transcript. Only the transcript path writes them, because a reset time is needed and the message fallback has none.

110. **Prompt and session hooks show the detail from the block.** When an unresolved block has a checked limit or reset time, `prompt-submit.sh` and `session-start.sh` add the detail after the reason. Why: the user sees which limit was hit and when it resets at the start of the next chat, at the start of the next chat, when it says to read HANDOFF.md first.

111. **No new config keys.** The feature has no on/off switch of its own, so `config/limit-handoff.conf.example` is unchanged. Why: the detail is only extra wording on the existing reason, so a new key would add a setting with no real use. A key can be added later with its own test.

112. **The CLI `recover` and `prompt` commands do not add a Limit line.** Only the StopFailure hook writes the `- Limit:` line, because it is the only path that has the hook's last message. Why: it keeps the output of the manual commands the same as before.

113. **Existing tests changed on purpose (two).** `test_attack_spec_output_has_exactly_the_specified_keys` now lists the new `limit` key. `test_notifier_shim_is_called` now expects the new title "Claude Code stopped: usage limit reached" (it used to be "Claude stopped: ..."). No other existing test was changed.

114. **Synthetic fixtures for the limit tests.** `tests/fixtures/limit_five_hour.jsonl`, `limit_seven_day.jsonl`, `limit_sidechain_only.jsonl` and `limit_hostile.jsonl` are made up. Their reset times are fixed: epoch 1793382000 is Fri 30 Oct 2026 17:40 UTC, which is 5:40pm in London, and epoch 1793610000 is Mon 02 Nov 2026 09:00 UTC. The tests set `TZ=UTC` when they check the formatted time. Why: exact checks need fixed values, and real transcripts must never be used.

115. **The suite count.** The suite has 313 checks: the 282 from before this feature, plus 31 new ones in `tests/test_limit_details.sh`.

116. **A repeat StopFailure is ignored for 120 seconds.** `hk_claim_stop` keeps the time of the first handled StopFailure for each chat in `<state>/handled/<session>`. A repeat within `LIMIT_HANDOFF_DEBOUNCE_SEC` seconds (default 120) is logged as "duplicate StopFailure for <sid> ignored", and nothing is written. Why: Claude Code can send several StopFailure events for one limit (bug 91419, subagent and helper failures). Without this there would be several recovered files and several clipboard copies.

117. **The marker is written before the slow work, under a lock.** The check and the write run under the lock for that marker file, so two hooks at the same moment cannot both pass. The marker is written with `hk_atomic_write`, not a plain `printf >`, because hard rule 2 says every write uses it. An empty session id shares the marker named `unknown`, the same name the file names already use. Changed by decision 170: there is now a started marker (this one) and a done marker, written after the handoff is saved. A catch-up retries a chat whose start never finished.

118. **Known limit: a second limit within the window is not recorded.** If a chat is resumed and hits a new limit within 120 seconds of the first one, that second StopFailure is ignored. The block keeps the first code and time. This is the cost of the window. `LIMIT_HANDOFF_DEBOUNCE_SEC=0` turns it off.

119. **`prompt_too_long` is a kit code, used by catch-up only.** It is in `HK_STOP_CODES`, so `hk_known_code` and `hk_reason_for` know it, and its reason is "context limit (prompt too long)". A StopFailure from Claude Code with this code is logged and skipped. `LIMIT_HANDOFF_ERRORS` is never checked for it. Why: Claude Code does not send this code, and the code must not become a handoff just because someone added it to the list.

120. **Catch-up runs at startup, resume and clear, never at compact.** It runs before the HANDOFF.md checks in `session-start.sh`, because it may create HANDOFF.md. Why: compact happens in the middle of a chat, which has not stopped.

121. **Which chats are checked.** Only plain `*.jsonl` files directly in the transcript's folder: no subfolders and no links. Their modification time must be within `LIMIT_HANDOFF_CATCHUP_HOURS` (default 48). The file name must be a safe session id (letters, digits, "_" and "-", 1 to 80 characters). A name with spaces or `$(...)` is skipped and never run. The current chat is skipped on startup and included on resume, because a resumed chat is the one that may have stopped.

122. **Handled chats do not use up the limit of three.** The newest chats that still need a check are read, at most three, with 300 lines each through jq. A chat with a handled marker (any age) is skipped before the count, so old handled chats cannot hide an unhandled cut-off chat. The limit keeps the start of a session fast. Trade-off: a limit chat that is behind three newer normal chats is not reached on a later start (see the open concern in the report).

123. **A chat qualifies only when its last real turn is the limit.** Only main-chain lines count, so a subagent copy is skipped. The last assistant line or real user prompt must be a synthetic limit line. A later real reply, or a later typed prompt, means the chat moved on. The error must be in `LIMIT_HANDOFF_ERRORS`, or the text must start with "Prompt is too long" (then the code is prompt_too_long). Its cwd, when it has one, must be the project folder or inside it. Both the folder path and its real path are accepted, because macOS links `/tmp` to `/private/tmp`. The filter is `lib/lastturn.jq`. Changed by decision 169: a limit line with no cwd no longer counts for catch-up (real limit lines carry one).

124. **The catch-up run is silent.** It has no clipboard copy and no notification, because the user is already in a new chat. The paste prompt file is still written. The child hook gets `LIMIT_HANDOFF_CATCHUP_RUN=1` and a payload built by jq, never by joining strings. It is run with `/bin/bash`, the same way the tests run it, so a lost executable bit cannot stop it.

125. **One line per handoff, printed before the usual text.** The line is printed only when the block for that chat is really in HANDOFF.md, so it is never wrong (for example when `LIMIT_HANDOFF_CREATE_IF_MISSING=0`). It shows the first 8 characters of the session id and the fixed reason text. Transcript text is never printed.

126. **Three new config keys.** `LIMIT_HANDOFF_CATCHUP` (1 or 0), `LIMIT_HANDOFF_CATCHUP_HOURS` (default 48) and `LIMIT_HANDOFF_DEBOUNCE_SEC` (default 120) are in `config/limit-handoff.conf.example`. They are read with `hk_bool_conf` and `hk_int_conf`, so the project file may set them, like the other non-trusted keys. This replaces decision 111, which said no keys were needed. The features now need an on/off switch and a window.

129. **The git section is text made in bash, passed into jq.** `hk_git_state DIR` builds the whole markdown section ("## Repository state (from git, when this file was made)" up to the closing fence) and prints it. `hk_render_recovered` gets it as an optional eighth argument and adds it with a jq `--arg`. jq never runs git, and the existing callers keep working because the argument is optional. Why: the spec wants jq to stay a pure formatter. The fence has to be known before the text is built, so it is worked out in bash with the same rule as `fence_for` (one more backtick than the longest run in the text, and at least four).

130. **Git gets settings that stop the repository from running programs.** Every command runs as `git -C DIR` with `-c core.fsmonitor=false -c core.untrackedCache=false -c core.pager=cat -c color.ui=false -c status.showUntrackedFiles=normal`, and the environment `GIT_OPTIONAL_LOCKS=0 GIT_TERMINAL_PROMPT=0 GIT_PAGER=cat`. stdin is `/dev/null` and errors are dropped. `GIT_DIR`, `GIT_WORK_TREE` and `GIT_INDEX_FILE` are removed for these commands, so a stray variable cannot point git at another repository. Why: a cloned repository controls its own `.git/config`, and git can run programs listed there (fsmonitor, filter drivers, external diff, textconv). The tests in `tests/test_git_state.sh` show that a plain git command runs those programs in a test repo, and that `hk_git_state` does not.

131. **Filter drivers are switched off by name.** `git config --name-only --get-regexp '^filter\.'` lists the driver names from the config. Reading config runs nothing. Each driver gets `-c filter.NAME.clean= -c filter.NAME.smudge= -c filter.NAME.process= -c filter.NAME.required=false`, which makes git use no program. A driver name with a character outside `A-Za-z0-9._-` makes the whole section go away, because the kit does not run git when it cannot be sure. Why: `git diff` runs a clean filter to compare file contents, so a filter in the repository's config would otherwise run.

132. **External diff and textconv are off in the command.** The diff summary is `git diff --no-ext-diff --no-textconv --no-color --stat HEAD`, and the last line is used. The test with a textconv program does not show that the flag is needed. On this git version `--stat` never ran the textconv program, even with `--textconv`. The flags stay as a safety margin, because the spec asks for them and a later git version or a different output form could run the program. The test checks the outcome (the program is not run) and records a plain patch diff as the control.

It may be set in the project file, like the other ordinary keys, because it can only turn the section off, and the commands above cannot run repository programs. It is documented in `config/limit-handoff.conf.example`. Why: a user who does not want git facts in the file, or who has a very large repository, can turn it off.

134. **The section is shown in one place for every path.** `hk_write_recovered` builds it for the project folder, so the StopFailure hook, the catch-up run, the PreCompact snapshot and the manual `prompt` command all get it. `recover --stdout` also adds it, so the printed text matches the saved file. Why: one rule for every recovered file. Paths in the status list are relative to the repository root, so a project in a subfolder still shows the whole repository.

135. **Limits on what is shown.** At most 30 status lines are listed. After that a line `... and N more` is put inside the fence. The last commit's subject is cut to 120 characters, and the branch name and the diff summary to 200. Control characters are removed from every line. A backtick in a branch name, a commit subject or a diff summary becomes an apostrophe, because those are written as inline text and a backtick could open a code span. A file name with backticks is only ever inside the fence, so it cannot break the layout. Why: the file must stay short and readable, and text from git must not change the markdown structure.

136. **Plain wording for the two special cases.** A repository with no commits shows `(no commits yet)` for the last commit, and the changes line says there is no diff summary. A clean working tree shows the sentence "The working tree is clean" in place of the empty code block. Why: a reader (often the model) must see clearly that nothing was checked, not see an empty block.

A very large repository could take long enough to stop the hook before HANDOFF.md is written. No timeout is added, because macOS has no built-in timeout command, and a timer written in bash would need to kill git. `LIMIT_HANDOFF_GIT=0` turns the section off. The section shows what git sees at the time it runs, not what was true earlier in the chat.

182. **The lock is a noclobber file, not a folder (found by the first CI run).** GitHub's `ubuntu-latest` became Ubuntu 26.04, whose `mkdir` is the Rust uutils version (0.10.0).
